---
title: "CDC-026: Multiclock crossing leg-pair report"
linkTitle: CDC-026
weight: 124
---

**Severity:** note

A crossing whose source or receiver runs on a muxed clock:
each side may arrive on several legs, and one leg pair can be
safe while another is not. One finding per endpoint lists the
clock sets, the mux selections behind them, every leg pair with
its relationship, and the destination chain depth. Multiple
clocks alone prove nothing; review the pairs, then waive or fix.

## Failing example

`fixtures/CDC-026/note_mux_union.sv`:

```systemverilog
// CDC-026: destination clocked by a $mux union of two async
// clocks. The crossing is synchronized, so only the leg-pair
// record fires: sets, pairs, select, and chain depth.
module note_mux_union (
    input  logic ca,
    input  logic cb,
    input  logic sel,
    input  logic d,
    output logic q
);

    logic mclk;
    always_comb begin
        mclk = sel ? cb : ca;
    end

    logic src_q;
    always_ff @(posedge ca) begin
        src_q <= d;
    end

    logic sync_1;
    always_ff @(posedge mclk) begin
        sync_1 <= src_q;
    end

    logic sync_2;
    always_ff @(posedge mclk) begin
        sync_2 <= sync_1;
    end

    assign q = sync_2;

endmodule
```

with `fixtures/CDC-026/note_mux_union.sdc`:

```tcl
create_clock -name ca -period 10.0 [get_ports ca]
create_clock -name cb -period 7.5  [get_ports cb]
set_clock_groups -asynchronous -group {ca} -group {cb}
set_input_delay -clock ca 1.0 [get_ports d]
set_input_delay -clock ca 1.0 [get_ports sel]
```

More failing cases: `note_nested_mux.sv`, `note_or_mux.sv`, `note_shared_select.sv`.
