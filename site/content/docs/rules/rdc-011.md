---
title: "RDC-011: One net drives both sync and async resets"
linkTitle: "RDC-011 One net drives both sync and async resets"
weight: 135
---

**Severity:** error

One resolved reset root reaches an async pin on some flop
and a sync control ($sdff SRST or a const-leg D-mux) on
another. Async users leave reset on the net's edge while
sync users wait for a clock, so the groups skew and their
handoff corrupts. Split the net or qualify one side.

## Failing example

`fixtures/RDC-011/bad_dual_use.sv`:

```systemverilog
// RDC-011: one reset net is the async reset of a_q and the sync
// reset of s_q. Each drives its own output, so synthesis keeps both
// uses. The two groups can never leave reset together.
module bad_dual_use (
    input  wire clk,
    input  wire rst,
    input  wire d,
    output wire qa,
    output wire qs
);
    reg a_q;
    always_ff @(posedge clk or posedge rst)
        if (rst) a_q <= 1'b0;
        else     a_q <= d;

    reg s_q;
    always_ff @(posedge clk)
        if (rst) s_q <= 1'b0;
        else     s_q <= d;

    assign qa = a_q;
    assign qs = s_q;
endmodule
```

with `fixtures/RDC-011/bad_dual_use.sdc`:

```tcl
create_clock -name clk -period 10.0 [get_ports clk]
set_input_delay -clock clk 1.0 [get_ports d]
set_input_delay -clock clk 1.0 [get_ports rst]
```
