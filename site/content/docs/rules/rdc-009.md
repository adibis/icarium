---
title: "RDC-009: Unqualified data crossing reset domains"
linkTitle: RDC-009
weight: 133
---

**Severity:** error

A flop's data input is driven from another reset domain with
no shared release: the source can come out of reset while the
receiver samples. Both sides need an async reset to trip it;
a side with none never releases, so unreset storage fed from
a reset domain stays silent. Clocks do not matter here.

## Failing example

`fixtures/RDC-009/bad_split_reset.sv`:

```systemverilog
// RDC-009: source and destination flops sit on different async
// resets under one clock. Same clock, different release order:
// the source can come out of reset while the receiver samples.
module bad_split_reset (
    input  wire clk,
    input  wire rst_a,
    input  wire rst_b,
    input  wire d,
    output wire q
);
    reg src_q;
    always_ff @(posedge clk or posedge rst_a)
        if (rst_a) src_q <= 1'b0;
        else       src_q <= d;

    reg dst_q;
    always_ff @(posedge clk or posedge rst_b)
        if (rst_b) dst_q <= 1'b0;
        else       dst_q <= src_q;

    assign q = dst_q;
endmodule
```

with `fixtures/RDC-009/bad_split_reset.sdc`:

```tcl
create_clock -name clk -period 10.0 [get_ports clk]
set_input_delay -clock clk 1.0 [get_ports d]
```
