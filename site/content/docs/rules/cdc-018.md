title: "CDC-018: Synchronizer chain deeper than the policy threshold"
linkTitle: "CDC-018 Synchronizer chain deeper than the policy threshold"
weight: 116
---

**Severity:** warning

A destination chain runs deeper than the configured threshold
(default 4). This is a policy check, not a defect: each extra
stage adds resolution time as well as latency, and fast clocks
or high data rates can need more than two. Stacked 2FF syncs
and refactor leftovers are the usual causes. Trim the chain,
set the threshold your library needs, or vouch the head.

## Suppression marks

This rule honors: `(* cdc_sync *)`.

## Failing example

`fixtures/CDC-018/bad_deep_chain.sv`:

```systemverilog
// CDC-018: a 4-deep destination chain. It resolves fine, but
// two stacked 2FF syncs smell of a doubled fix or a leftover
// wrapper. Depth checks pass; only the cascade rule fires.
module bad_deep_chain (
    input  logic src_clk,
    input  logic dst_clk,
    input  logic d_in,
    output logic q_out
);

    logic src_q;
    always_ff @(posedge src_clk) src_q <= d_in;

    logic meta, sync_q, sync2_meta, sync2_q;
    always_ff @(posedge dst_clk) begin
        meta       <= src_q;
        sync_q     <= meta;
        sync2_meta <= sync_q;
        sync2_q    <= sync2_meta;
    end

    assign q_out = sync2_q;

endmodule
```

with `fixtures/CDC-018/bad_deep_chain.sdc`:

```tcl
create_clock -name src_clk -period 10.0 [get_ports src_clk]
create_clock -name dst_clk -period 7.5  [get_ports dst_clk]
set_clock_groups -asynchronous -group {src_clk} -group {dst_clk}
set_input_delay -clock src_clk 1.0 [get_ports d_in]
```
