---
title: "RDC-010: Reset synchronizer chain record and checks"
linkTitle: RDC-010
weight: 134
---

**Severity:** note

Every recognized reset synchronizer is recorded for review:
stages, clock, polarity, head constant, async root. Shape
defects report beside the record: a chain on the wrong clock
for its consumers, internal taps feeding resets, and gates
editing the output all break the release contract; consumers
on the raw root in a served domain report at warn.

## Failing example

`fixtures/RDC-010/bad_chain_clock.sv`:

```systemverilog
// RDC-010: chain runs on clk_a but serves a consumer on clk_b.
// The release edge arrives in the wrong domain (RDC-001 agrees
// on the foreign reset); the chain clock finding is RDC-010's.
module bad_chain_clock (
    input  wire clk_a,
    input  wire clk_b,
    input  wire rst_n,
    input  wire d,
    output wire q
);
    reg s1, s2;
    always_ff @(posedge clk_a or negedge rst_n) begin
        if (!rst_n) s1 <= 1'b0;
        else        s1 <= 1'b1;
    end
    always_ff @(posedge clk_a or negedge rst_n) begin
        if (!rst_n) s2 <= 1'b0;
        else        s2 <= s1;
    end

    reg qq;
    always_ff @(posedge clk_b or negedge s2) begin
        if (!s2) qq <= 1'b0;
        else     qq <= d;
    end

    assign q = qq;
endmodule
```

with `fixtures/RDC-010/bad_chain_clock.sdc`:

```tcl
create_clock -name clk_a -period 10.0 [get_ports clk_a]
create_clock -name clk_b -period 7.0 [get_ports clk_b]
set_clock_groups -asynchronous -group {clk_a} -group {clk_b}
set_input_delay -clock clk_b 1.0 [get_ports d]
```
